# Задача: полноценная система аккаунтов и баг с выкидыванием из сессии

Репозиторий: `lengway/bc2026` (Next.js 16, React 19, Postgres без ORM, zod 4, Vitest, pnpm). Перед работой прочитай `CONTEXT.md`, `DESIGN_HANDOFF.md`, `AGENTS.md`. Работай в ветке, PR в `main`. Перед PR: `pnpm lint && pnpm typecheck && pnpm test` зелёные (бэкенд-тесты требуют `TEST_DATABASE_URL`).

Где сейчас авторизация:
- `src/modules/identity/` — `service.ts` (magic link, сессии), `security.ts` (cookie `HttpOnly; SameSite=Lax; Secure`), `repo.ts` (поиск сессии по `token_hash`, `revoked_at IS NULL AND expires_at > now`), `smtp.ts`.
- `src/app/api/auth/` — `magic-link`, `verify`, `session`, `logout`, `guest`, `options`.
- Таблицы `users`, `sessions`, `auth_tokens` — `db/migrations/001_initial.sql`. Новые изменения схемы — только новой миграцией (старые редактировать нельзя, проверяются чек-суммы).
- Прод: `https://gambit.lengway.me`, за Cloudflare → nginx → контейнер `web`. Deploy: Docker Compose.

## Часть 1. Баг: пользователя выкидывает из аккаунта после прохождения кейса (делать первым)
Пользователь вошёл по magic link, прошёл кейс — и оказался разлогинен. Найди причину и почини. Проверь по порядку:
1. Срок жизни сессии: какой `expires_at` ставится при входе. Если короткий — сделать 30 дней со скользящим продлением (продлевать при активности, если до истечения меньше половины срока), cookie `Max-Age` синхронизировать.
2. Нет ли кода, который отзывает сессию (`revoked_at`) или ставит пустую cookie при сдаче кейса, ошибке 401 от одного эндпоинта, переходе на `/review`, ротации сессии.
3. Фронт: не трактует ли клиент любой 401/403 (например, `PAYWALL` или `FORBIDDEN` при открытии разбора или сертификата) как «выйти из аккаунта» и не вызывает `/api/auth/logout`. Ошибка прав ≠ выход.
4. Cookie за прокси: `Secure` при `X-Forwarded-Proto: https`, нет лишнего `Domain`, `Path=/`. Next.js middleware/`proxy` не теряет cookie на редиректах.
5. Гостевая сессия (`is_guest`) истекает за 24 часа — убедись, что обычный пользователь не попадает в гостевой режим.

Напиши тест, который воспроизводит баг: вход → создание кейса → сдача → `GET /api/auth/session` всё ещё возвращает того же пользователя.

## Часть 2. Аккаунты: email + пароль, magic link остаётся
### Функции
- **Регистрация**: email, пароль, имя (имя идёт в сертификат). Подтверждение email письмом (ссылка, 24 часа). До подтверждения можно пройти онбординг и первый кейс, но сертификат выдаётся только подтверждённому email.
- **Вход**: email + пароль. Рядом — «Email me a sign-in link» (текущий magic link).
- **Забыли пароль**: письмо со ссылкой сброса (одноразовая, 30 минут) → форма нового пароля → все прочие сессии отзываются.
- **Настройки аккаунта** `/settings`: имя, email (смена — с подтверждением на новый адрес), смена пароля (нужен текущий), «Sign out of all devices», удаление аккаунта (с подтверждением, удаляет персональные данные; сертификаты деактивируются).
- **Вход через Google** — по желанию, если успеешь: OAuth через `openid-client` или аналог, связывание с существующим аккаунтом по подтверждённому email.

### Безопасность (обязательно)
- Пароли: `argon2id` (пакет `@node-rs/argon2` или `argon2`), минимум 10 символов, проверка по списку частых паролей не нужна.
- Все токены (подтверждение, сброс, magic link, сессии) хранятся только в виде хэша, одноразовые, с истечением.
- Ответы входа и сброса не раскрывают, существует ли email («If an account exists, we sent an email»), одинаковое время ответа.
- Rate limit через существующую таблицу `rate_limits`: вход 10 попыток / 15 мин на email+IP, сброс 3 / час на email. IP брать из `X-Real-IP` (его ставит nginx из `CF-Connecting-IP`).
- Смена пароля и сброс отзывают остальные сессии. Сессия ротируется при входе.
- CSRF: POST-эндпоинты принимают только `Content-Type: application/json` и проверяют `Origin` = `APP_URL`.

### Схема (новая миграция)
- `users`: `password_hash text NULL`, `email_verified_at timestamptz NULL`, `display_name` (если нет).
- `auth_tokens`: колонка `purpose` (`magic_link | verify_email | reset_password | change_email`) и `meta jsonb` для нового email. Либо отдельная таблица — на твой выбор, но одноразовость и хэши обязательны.

### API (контракты в `src/contracts/auth.ts`, zod)
`POST /api/auth/register` · `POST /api/auth/login` · `POST /api/auth/verify-email` · `POST /api/auth/forgot-password` · `POST /api/auth/reset-password` · `POST /api/auth/change-password` · `POST /api/auth/change-email` · `POST /api/auth/logout-all` · `DELETE /api/account`. Ошибки в общем формате `{error:{code,message}}`.

### UI (в стиле приложения: токены из `globals.css`, компоненты из `src/ui`, без новых цветов)
- `/login` — табы «Password» / «Email link», ссылки «Create account», «Forgot password?».
- `/signup`, `/forgot-password`, `/reset-password?token=`, `/verify-email?token=`, `/settings`.
- Поля с `<label>`, показ/скрытие пароля, понятные ошибки под полем, кнопка блокируется во время запроса.
- После входа — возврат на страницу, с которой отправили на логин (`?next=`, только относительные пути).
- Письма (`src/modules/identity/smtp.ts`): от имени Gambit, а не «Skills workspace»; короткий текст, ссылка, срок действия.

### Тесты
- регистрация → подтверждение → вход паролем → сессия жива после сдачи кейса;
- неверный пароль, rate limit, неподтверждённый email не получает сертификат;
- сброс пароля одноразовый, истёкший токен отклоняется, остальные сессии отозваны;
- ответы не раскрывают существование email;
- security-тест: в ответах нет `password_hash` и сырых токенов.
