# Задача: упростить экран разбора, починить оценку ходов, Enter в Copilot

Репозиторий: `lengway/bc2026` (Next.js 16, React 19, Tailwind 4, shadcn, zod 4, Vitest, pnpm). Перед работой прочитай `CONTEXT.md`, `DESIGN_HANDOFF.md` и `AGENTS.md`. Работай в ветке, открой PR в `main`. Проверка перед PR: `pnpm lint && pnpm typecheck && pnpm test` зелёные.

## Проблема

Экран разбора (`/review/[id]`) сейчас выглядит как технический отчёт: блоки «Observed assistance», «Checking and applying AI advice», 10 строк «not observed», «Why this score?» с формулой, «Activity observations» с сырым JSON (`{"clickCount":43,...}`), «Descriptive text characteristics». Обычный пользователь ничего не понимает. Плюс в реальном кейсе **все 5 ходов получили «Not enough evidence»**, Accuracy не посчитана — хотя ходы нормальные. То есть главная фишка продукта не работает.

## Часть 1. Бэкенд: почему ходы не оцениваются (делать первым)

В реальном прогоне `eval.moves` (модель `gpt-6.1-sol`) вернул ответ, но после проверки в `src/modules/evaluation/scoring.ts` каждый ход ушёл в `assessmentStatus: 'insufficient_evidence'` с текстом «Criterion not supplied», «No supporting evidence was supplied».

1. Воспроизведи на записанном ответе модели: возьми строку из `llm_calls` (prompt_id `eval.moves`) последнего кейса — на сервере можно посмотреть через `psql` в контейнере postgres. Найди, на каком условии проверка отбрасывает ход: нет `rubricRef`, `evidence` пустой, цитата не совпадает с текстом хода дословно, id критерия не совпадает с рубрикой и т. п.
2. Почини причину, а не симптом. Скорее всего одно из:
   - промпт `src/prompts/eval.moves.v2.md` не требует явно `rubricRef` и `evidence` с дословными цитатами — уточни формат и дай пример;
   - проверка цитат слишком строгая (регистр, пробелы, кавычки, переносы) — нормализуй перед сравнением;
   - id критериев в ответе модели не совпадают с id в рубрике — передавай модели точный список id.
3. Правило продукта: ход **получает метку**, если модель её дала и указала критерий; «insufficient evidence» — исключение для реально пустых ходов вроде «Hello!», а не норма.
4. Тест: golden-тест на реальном транскрипте из этого кейса (5 ходов, переговоры о net-60 с Marisol Velez, Prairie Bend Packaging) — минимум 4 из 5 ходов оценены, Accuracy не null.

## Часть 2. Новый экран разбора — как Game Review на chess.com

Файл: `src/screens/review/review-screen.tsx` (презентационный, только props) + контейнер в `src/app/(frontend)/(app)/review/[id]`. Используй готовые компоненты из `src/ui` (`AccuracyStat`, `MoveLabelBadge`, `TrustCurveChart`, `MoveDetail`, `ChatMessage`, `OutcomeBadge`) и токены из `src/app/globals.css`. Стиль — строгий, как сейчас: никаких новых цветов, эмодзи и градиентов.

### Раскладка (десктоп, ≥1024px)

```
┌───────────────────────────────────────────────────────────────┐
│ Case review · Название кейса          [Next case] [Share]     │
│ 74%  Deal won   !! 1  ! 2  — 4  ?! 1  ? 0  ?? 1               │
│ Одна фраза-итог (evaluation.summary)                          │
├──────────────────────────────────────┬────────────────────────┤
│ ДИАЛОГ (повтор переписки)            │ ТЕКУЩИЙ ХОД            │
│                                      │ ?? Blunder · Move 3/5  │
│  Marisol: ...                        │ Why: ...               │
│  You: ...  [!]                       │ Better move: ...       │
│  Marisol: ...                        │ What Marisol thought:… │
│ ▶You: ...  [??]  ← подсвечен         │ Trust 61 → 38  −23     │

│ Кривая доверия (клик по точке = переход к ходу)               │
└───────────────────────────────────────────────────────────────┘
```

### Поведение

- **Диалог** — та же переписка, что была в кейсе (сообщения пользователя и персонажа по порядку; твисты — как входящее письмо). Каждое сообщение пользователя помечено `MoveLabelBadge` справа. Сообщения после текущего хода приглушены (opacity ~40%), как непроигранные ходы в шахматах.
- **Стрелки**: «В начало», «Назад», «Вперёд», «В конец» и счётчик `3 / 5`. Клавиатура: ← и → на странице переключают ход (если фокус не в поле ввода). При смене хода диалог плавно прокручивается к текущему сообщению (уважать `prefers-reduced-motion`).
- **Текущий ход** справа — `MoveDetail`: метка, «Your move» не дублировать (он уже подсвечен в диалоге), «Why», «Better move», «What <имя> was thinking», изменение доверия.
- **Список ходов** под ним — `MoveTimeline`: клик по строке = переход к этому ходу (диалог прокручивается, стрелки синхронизируются). Это и есть таймлайн.
- **Кривая доверия** внизу — `TrustCurveChart`, клик по точке = переход к ходу. Все три способа навигации (стрелки, список, кривая) показывают один и тот же выбранный ход.
- Открывать на первом ключевом ходе (`evaluation.topMoves[0]`), иначе на первом.
- **Мобильный (<1024px)**: сверху сводка, ниже диалог с прилипшей снизу панелью стрелок; «Текущий ход» — раскрывающаяся карточка под подсвеченным сообщением; список ходов — в `Sheet` по кнопке «All moves».

### Что убрать с экрана

Убрать для пользователя полностью: «Activity observations», сырой JSON, «Descriptive text characteristics», «Observation coverage», формулу расчёта, таблицу очков за метки, 10 строк критериев «not observed», служебные дисклеймеры про authorship.

Оставить в одном свёрнутом блоке внизу `<details>` «How this was scored» — 3–4 строки простым языком:

- «Each message you sent got a label, from Brilliant to Blunder. Accuracy is the average.»
- «AI dependency: 31% of your text closely followed Copilot. Copilot trap: caught / missed.»
- «Moves without enough content to judge (like “Hello!”) are not counted.»

Метрики AI вынести в одну строку в сводке сверху: `AI dependency 31% · Copilot trap missed`. Если значения нет — не писать «Not enough evidence», а просто не показывать.

Если оценка не удалась целиком (все ходы без оценки) — вместо пустой сводки показать понятное состояние: «We couldn’t score this case. Your conversation is saved below.» + кнопка «Try a new case». Но после Части 1 это должно быть редкостью.

Тексты — английский, коротко, без восклицательных знаков.

### Данные

Экрану нужен транскрипт кейса для диалога. Если `/api/cases/:id/review` его не отдаёт — добавь в ответ публичные события (`seq, actor, type, content, createdAt`, без скрытых полей) по образцу `CertificateFull.transcript`. Скрытое (`innerThought` до сдачи, рубрика, `realMotive`) по-прежнему не уходит на клиент до сдачи — проверь security-тест.

### Тесты (Vitest + Testing Library)

- стрелки «Вперёд/Назад» меняют выбранный ход, на краях кнопки disabled;
- клик в списке ходов и клик по точке кривой выбирают тот же ход, что и стрелки;
- ← / → с клавиатуры переключают ход;
- блоки «Activity observations» и сырой JSON больше не рендерятся;
- состояние «We couldn’t score this case» при нуле оценённых ходов.
