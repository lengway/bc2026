# Accounts and session continuity implementation plan

> Execute inline using superpowers:executing-plans. User authorized implementation on 2026-11-14; no new product design or frontend work.

**Goal:** Diagnose logout after submitting a case, preserve authenticated sessions, and implement the backend account lifecycle specified in `docs/spec/accounts.md`.
**Architecture:** Extend the current identity module, Zod contracts, PostgreSQL and HTTP handlers. Use Argon2id and purpose-bound, hashed email tokens. Keep magic links and isolated guest sessions. No external auth service or optional Google OAuth in this scope.
**Stack:** Existing Next.js/Node/PostgreSQL; `@node-rs/argon2` for passwords.

## Constraints and decisions

- Frontend, design and CI belong to teammates. User additionally authorized changes to src/proxy.ts and src/app/_lib/auth/server.ts for server-side auth only. Push and PR remain the user's responsibility.
- Keep old migrations unchanged; add one migration. Keep existing users, cases and magic links working.
- Normal sessions: 30 days, refresh when less than 15 days remain; guests: fixed 24 hours. Refresh cookie with database expiry. Session tokens are reusable; email tokens are single-use.
- Registration: email/password/displayName; verification for 24 hours; unverified members can practice but cannot publish certificates. Verification enables certificates for already evaluated cases. Guest demo certificates remain clearly marked demonstrations.
- Reset links: 30 minutes, single-use; revoke other sessions. Password/email changes and deletion require current password, or a recent magic-link sign-in for passwordless users. Never expose hashes or raw tokens in JSON.
- Generic registration/reset responses, generic invalid login errors, equivalent password hashing paths. Exact wall-clock equality across networks is not promised.
- Deletion erases owned records and unpublishes certificates; log ownership must cover intake records as well as case records.
- Auth POST/PATCH/DELETE require JSON and same-origin; payment webhook retains its separate signature protocol. Trust X-Real-IP only behind a sanitizing proxy.
- No paid LLM calls. SMTP tests use captured mail, real local PostgreSQL. No production migration/restart until changes and current deployment are inspected and validated.
